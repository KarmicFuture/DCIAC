# Plan · 2026-11-21 · Operate/Plan sub-navigation and page heading

Branch: `ux/2026-11-21-cycle`  
Backlog item: **rank 3** in `docs/ux-backlog.md`. Operate/Plan sub-navigation uses tab roles without tab interaction semantics, and the page heading stays "Operate" or "Plan" on every sub-view (WCAG 4.1.2, 1.3.1, 2.4.6). Severity 3, effort S.

## Why this one

- **Best impact for the effort.** Items 1 and 2 are severity 4, but they are M and L. Item 1 needs a focus trap, initial focus, Escape, and an inert background. It has to survive `render()` replacing the shell markup on every state change, so it touches three files and the outlet safety flow. Item 2 is a cross-view keyboard model for the floor scene. Neither fits comfortably in one ~300-line cycle without risk to safety-critical paths.
- **Every Operate and Plan user hits it on every screen.** That covers 10 screens: Rack, Port map, Control, Sessions, One-line, Fleet, Campus, Halls, Models, and DCIM.
- **The fix is contained.** One source file (`src/ui/rail.ts`) holds the markup, plus one CSS selector. The rest is updating existing Playwright assertions. Nothing touches the outlet, alarm, or KVM logic.

## Problem (today, from the code)

`src/ui/rail.ts`:

- `viewTabs()` renders `<div class="view-tabs" role="tablist">` with `<button role="tab" aria-selected="true|false">` per sub-view. There is no `tabpanel` and no `aria-controls`. Arrow, Home, and End keys don't move between tabs, and there is no roving `tabindex`. Each "tab" is really a `data-act="nav"` button that changes `state.view` and the URL hash, so it is page navigation. A screen reader announces "tab, 3 of 6, selected", and users then expect tab-panel behaviour that isn't there.
- `operateHead()` always renders `<h1>Operate</h1>`, and `planHead()` always renders `<h1>Plan</h1>`. So Rack, Port map, Control, Sessions, One-line, and Fleet all have the same heading, as do Campus, Halls, Models, and DCIM. Heading navigation can't tell the screens apart.
- `topbar()` (the narrow-screen header) uses `VIEW_TITLE`, which maps every Operate view to "Operate" and every Plan view to "Plan". The mobile header has the same problem.
- `styles.css` around line 372 styles the selected chip with `.view-tabs button[aria-selected="true"]`.

Selectors the builder must not break:

- `e2e/access.spec.js` clicks `nav [data-view="rack"]` and expects `nav [data-view]` to have count 4 (the rail). The sub-navigation therefore **must not** become a `<nav>` element. Use `role="navigation"` on the existing `div`, as `tabbar()` already does.
- Many specs click `.view-tabs [data-view="…"]`. Keep the `view-tabs` class, `data-act="nav"`, and `data-view` attributes unchanged.

## User story

As an operator using a keyboard or screen reader on Rack A14, when I switch between Rack, Port map, Control, Sessions, One-line, and Fleet (or Campus, Halls, Models, and DCIM), I want the page heading and the sub-navigation to tell me which screen I'm on. I also want the sub-navigation announced as the links it actually is, so I don't expect tab-panel keys that do nothing.

## Change (for the builder)

1. In `viewTabs(tabs)`, take a group label ("Operate" or "Plan") and render:
   `<div class="view-tabs" role="navigation" aria-label="Operate views">` (or `"Plan views"`).
   - Remove `role="tablist"`, `role="tab"`, and `aria-selected`.
   - The current sub-view button gets `aria-current="page"`. The other buttons get no `aria-current`.
   - Keep `type="button"`, `data-act="nav"`, `data-view`, and the existing label text, including the " · N" session count on Sessions.
2. Make the `<h1>` name the sub-view as `<group> · <sub-view label>`, using the labels from `OPERATE_TABS` and `PLAN_TABS`:
   - Operate: `Operate · Rack`, `Operate · Port map`, `Operate · Control`, `Operate · Sessions`, `Operate · One-line`, `Operate · Fleet`
   - Plan: `Plan · Campus`, `Plan · Halls`, `Plan · Models`, `Plan · DCIM`
   - The heading never includes the session count.
3. Make `topbar()`'s `.topbar-view` show the same `<group> · <label>` string for Operate and Plan views. Derive it from the same tab arrays so there is one source of truth. Floor, Manage, Audit, and Simulate titles stay as they are.
4. In `styles.css`, change `.view-tabs button[aria-selected="true"]` to `.view-tabs button[aria-current="page"]` with the same declarations. Don't change the global `:focus-visible` rule (around line 131); it already gives the chips a visible focus ring.
5. Update existing Playwright assertions to the new heading and state (see the file list), and add one focused spec.

## Acceptance criteria

Each criterion is observable in Playwright or by hand at `#/rack`, `#/map`, `#/control`, `#/sessions`, `#/oneline`, `#/fleet`, `#/plan`, `#/halls`, `#/models`, and `#/dcim`.

1. **No tab roles.** On every Operate and Plan view, `.view-tabs [role="tab"]`, `[role="tablist"]`, and `.view-tabs [aria-selected]` each have count 0.
2. **Named navigation landmark.** `page.getByRole("navigation", { name: "Operate views" })` is visible on each Operate view, and `getByRole("navigation", { name: "Plan views" })` is visible on each Plan view. The rail's own `nav [data-view]` count stays 4.
3. **Current sub-view marked.** Exactly one `.view-tabs [aria-current="page"]` exists on each of the 10 views, and its `data-view` equals the current view. For example, on `#/control` it is `data-view="control"`.
4. **Heading names the screen.** `h1` has exact text `Operate · <label>` or `Plan · <label>` for each of the 10 views, as listed in Change step 2. On `#/sessions` with an open session, the `h1` is still exactly `Operate · Sessions` (no count), and the Sessions chip still shows ` · N`.
5. **Mobile header matches.** At a 390×844 viewport, `.topbar-view` shows the same `<group> · <label>` text as the `h1` on `#/map` and `#/dcim`.
6. **Keyboard access unchanged.** From the `h1` region, Tab reaches each sub-view chip in visual order. Pressing Enter or Space on a focused chip navigates: the URL hash changes, and the `h1` and `aria-current` update. Arrow keys are not required.
7. **Focus is visible.** A chip focused by keyboard shows a visible outline: computed `outline-style` is not `none` on `:focus-visible`. The selected chip keeps its filled `--action` background, now driven by `aria-current="page"`.
8. **Other headings unchanged.** `h1` stays `Audit` on `#/audit` and `Simulate` on `#/simulate`. Floor and stage still render no `h1`, so `hall.spec.js` and `stage.spec.js` still pass unchanged.
9. **Suite green.** `npm test` in `prototypes/access-control` (vite build, then Playwright) passes with no skipped or removed tests. The total diff is under about 300 lines.
