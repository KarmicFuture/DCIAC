## Why this slice

- **Pan is pointer-only, and zoom isn't.** `hudHtml()` (`src/views/floor.ts` line 1068) already draws `<div class="zoom-cluster" role="group" aria-label="Zoom">` with **Zoom in**, **Zoom out**, and **Reset view** (`data-act="floor-zoom"`). There is no keyboard way to move the camera sideways, so a keyboard user who zooms in can't see the part of the hall or yard that is off-stage. The only way back is Reset.
- **Everything it needs already exists.** `cameraTransform()` (line 97) already emits `translate(panXpx,panYpx)` from `state.floor.panX` / `panY`. `applyCamera()` (line 109) writes `.world` `style.transform` without a full render, so focus stays on the button that was pressed. `zoomFloor()` (line 1974) shows the pattern: stop a walk, change state with `clamp()`, call `applyCamera()`. Its `"reset"` branch already sets `panX` and `panY` to 0, so Reset view also undoes pan.
- **No CSS.** `.zoom-cluster` already styles a button row, and the global `:focus-visible` rule (`styles.css` line 131) covers buttons.
- **Always testable.** The result is a string on `.world` `style.transform`, with no timing, picking, or 3D geometry involved.
- **Estimate:** about 30 lines across `floor.ts` and `render.ts`, plus about 100 lines in one new spec, roughly 130 lines in total.

## Problem (today, from the code)

1. **No keyboard pan.** `panX` / `panY` only change through pointer drag (`onPointerDown` / `onPointerMove`) or walk/briefing/route resets. A keyboard user can zoom but can't move the view.
2. **Zooming in can strand the view.** After **Zoom in**, parts of the hall are off-stage, and the only keyboard option is **Reset view**, which also undoes the zoom.

## User story

As a keyboard operator on the Floor view, I want **Pan left**, **Pan right**, **Pan up**, and **Pan down** buttons next to the zoom buttons, so I can move the view to the part of the hall or yard I need without a mouse, and keep my focus on the button while I press it repeatedly.

### 2. `prototypes/access-control/src/views/floor.ts` — new `panFloor(dir)` next to `zoomFloor()` (line 1974)

```ts
export function panFloor(dir) {
  if (runtime.walk) stopWalk(false, false);
  const step = 48;
  if (dir === "left") state.floor.panX -= step;
  else if (dir === "right") state.floor.panX += step;
  else if (dir === "up") state.floor.panY -= step;
  else if (dir === "down") state.floor.panY += step;
  state.floor.panX = clamp(state.floor.panX, -480, 480);
  state.floor.panY = clamp(state.floor.panY, -320, 320);
  applyCamera();
}
```

- Signature: `export function panFloor(dir: "left" | "right" | "up" | "down" | string | undefined): void` (untyped `dir` to match `zoomFloor(dir)`). An unknown `dir` only re-clamps and re-applies; it doesn't throw.
- Call `applyCamera()` only. **Don't** call `render()`, so focus stays on the button.
- Don't change `zoom`, `pitch`, `yaw`, `chassisZoom`, `chassisPitch`, `chassisYaw`, or orbit state.

## Acceptance criteria

All criteria are checked in one new spec, `e2e/floor-pan.spec.js`. Setup: use a 1440×900 viewport, go to `/#/floor`, sign in as `dsvs.operator` (same helper as `floor-grid.spec.js`), and wait until `#app` doesn't contain "Loading the asset repository". **Don't open the List.** Steps marked "keyboard" use `page.keyboard`.

1. **The Pan group is there and comes first.** `[role="group"][aria-label="Pan"]` has count 1 and contains exactly four buttons with accessible names `Pan left`, `Pan right`, `Pan up`, `Pan down`, in that order. Page-wide, `[data-act="floor-pan"]` has count 4. In DOM order, the Pan group comes before `[role="group"][aria-label="Zoom"]` (for example `pan.compareDocumentPosition(zoom) & Node.DOCUMENT_POSITION_FOLLOWING` is non-zero).
2. **Keyboard reaches Pan left with a visible focus ring.** Focus `#floor-list-toggle`, then press Tab (keyboard) at most 8 times until `document.activeElement` is the `Pan left` button. Its computed `outline-style` is not `none`.
3. **Enter pans and keeps focus.** Record `.world` `style.transform` as `before`. Press Enter (keyboard). Then:
   - `.world` `style.transform` is not equal to `before`, and the `translate(` portion changed (panX moved by 48).
   - `document.activeElement` is still the `Pan left` button.
   - `.scene.walking` has count 0.
4. **Left then right cancels.** Press Tab (keyboard) once to reach `Pan right` (or focus it and press Enter via keyboard). Press Enter. `.world` `style.transform` equals `before` exactly.
5. **Reset view undoes pan.** Move focus to `Pan up` and press Enter (keyboard); the transform is not equal to `before`. Move focus to `[data-act="floor-zoom"][data-dir="reset"]` and press Enter (keyboard). `.world` `style.transform` contains `translate(0px,0px)`, or its `translate(` portion matches a fresh load's (pan 0). The three Zoom buttons (`Zoom in`, `Zoom out`, `Reset view`) still exist.
6. **Pointer camera is untouched.** Don't assert drag behavior. After the steps above, the Zoom group (`[role="group"][aria-label="Zoom"]`) is still present with count 1, and the Pan group still has 4 buttons.
7. **Existing specs still pass unchanged:** `floor-grid.spec.js` in particular, plus `floor-feeds.spec.js`, `floor-list.spec.js`, `floor-pipes.spec.js`, `floor-hall.spec.js`, `floor-alarm.spec.js`, `floor-alarm-jump.spec.js`, `floor-drag.spec.js`, `floor-rack3d.spec.js`, `stage.spec.js`, and `hall.spec.js`.
