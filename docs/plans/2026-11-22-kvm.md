# Plan · 2026-11-22 · KVM console: name it, say where keys go, and describe the typed echo

Branch: `ux/2026-11-21-cycle`  
Backlog item: **rank 5** in `docs/ux-backlog.md`. The KVM console is a focusable generic container with click-to-type and a typed echo that is not named or described, so assistive-tech users cannot tell where keyboard input goes (WCAG 4.1.2, 1.3.1, 2.4.6). Severity 3, effort M.

## Why this one

- **Ranks 1, 3, and 4 are done.** Rank 2 (floor keyboard model) is effort L. It needs a keyboard model across halls, pods, racks, feeds, and pipes in a 1,900-line view, and it doesn't fit one ~300-line cycle.
- **Rank 5 is the only open item that fits.** It is severity 3 and sits on the KVM failover path, which is how operators reach a tray when the BMC or RDP desktop is gone.
- **The whole item fits; no slice is needed.** Reading the code:
  - Both console variants are rendered by one function, `kvmBody()` in `src/views/sessions.ts` (lines 53–93): the RDP-failover variant (`.rdp.kvm-take`, lines 54–65) and the BIOS/OS variant (`.bios`, lines 84–92).
  - Key handling in `src/ui/render.ts` `onKeyDown()` (lines 725–736) finds the console with `closest("[data-kvm]")` and writes to `[data-keys]` inside it. Both hooks stay, so `render.ts` doesn't need to change.
  - `.sr-only` already exists in `styles.css` (line 984), and the global `:focus-visible` rule (line 131) already applies to the console.
  - The estimate is about 25 lines in `sessions.ts`, 0–3 in `styles.css`, and about 110 in one new spec, for roughly 140–160 lines in total.

## Problem (today, from the code)

`kvmBody()` renders, for the BIOS/OS variant:

```html
<div class="toggle">
  <button type="button" class="act" data-act="screen" data-session="S" data-screen="bios" aria-pressed="false">BIOS</button>
  <button type="button" class="act" data-act="screen" data-session="S" data-screen="os" aria-pressed="true">OS</button>
</div>
<div class="bios" data-kvm="S" tabindex="0" id="kvm-S" data-focus-key="kvm-S">
  <div>GPU Tray 01 graphical console</div> … <div>HTML5 keyboard attached</div>
  <div class="keys">Typed <span data-keys></span></div>
</div>
<p class="fine">Click the console, then type. HTML5 viewer. Java and JNLP are unsupported.</p>
```

and, for the RDP-failover variant, the same toggle plus `<div class="rdp kvm-take" data-kvm="S" tabindex="0" …>` wrapping an `.rdp-bar` ("MPU2 KVM · HTML5", "port N"), the failover copy, and the same `.keys` echo, followed by the same `.fine` instructions.

The problems:

1. **The console has no role and no name (4.1.2).** It is a `tabindex="0"` `<div>`. When it gets focus, screen readers announce nothing useful, or read its whole text as one run ("GPU Tray 01 graphical console Ubuntu 24.04 LTS … Typed"). Nothing says it is a KVM console, which device it drives, or which screen (BIOS or OS) it shows.
2. **Screen readers swallow the keys.** In browse mode, NVDA and JAWS keep single-letter keys for quick navigation unless the focused element is an application or a form control. A generic focusable `div` gets neither, so `onKeyDown` never sees the operator's keys. That is the "KVM failover is opaque" impact in the backlog.
3. **The instructions aren't tied to the console (1.3.1).** "Click the console, then type." is a separate `<p>` after the console. It isn't the console's description. It also says only "click", which tells keyboard users nothing; Tab works today, but nothing says so, and nothing says that Tab leaves the console.
4. **The typed echo has no label relationship and no empty state (1.3.1).** "Typed" and the `[data-keys]` span are plain text. When nothing has been typed, it reads "Typed" followed by nothing.
5. **The BIOS/OS toggle has no context (2.4.6).** With several KVM sessions open, the Sessions view has several identical "BIOS" and "OS" buttons, and nothing groups them or says which console they switch.

Other code that depends on this markup:

- `src/ui/render.ts` `onKeyDown()` (lines 725–736): needs `[data-kvm]` on the console and `[data-keys]` inside it. It replaces the span's `textContent` with `session.keys` on each key.
- `src/domain/demo.ts` (lines 623 and 632): targets `.session.kvm .bios, .session.kvm`.
- `e2e/mp1000-demo.spec.js` (lines 46 and 48): `toContainText` on `.session.kvm .bios` ("Ubuntu 24.04", "Boot mode").
- `e2e/access.spec.js` (lines 55–61): launches a KVM session as ReadOnly and checks the media controls.
- `styles.css`: `.bios` (line 912), `.keys` (line 923), `.toggle` (line 924), `.rdp.kvm-take` (lines 816–817).

## User story

As a keyboard or screen-reader operator who has failed over to a KVM console, I want the console to tell me what it is, which device and screen it drives, how to send keys to it and how to leave it, and what I have typed so far. That way I know my keystrokes are going to the tray, not to the page.

## Change (for the builder)

All changes are in `kvmBody()` in `src/views/sessions.ts`, in both variants. Pass every interpolated value through `esc()`.

1. **Make the console an application with a name.** On the `[data-kvm]` element (both `.bios` and `.rdp.kvm-take`), add:
   - `role="application"`. This is a remote-keyboard surface, so screen readers should pass keys through to it.
   - `aria-label`:
     - BIOS/OS variant: `"KVM console for " + d.name + ", " + (s.screen === "bios" ? "BIOS" : "OS") + " screen"`.
     - RDP-failover variant: `"KVM failover console for " + d.name + ", OS screen"`.
   - `aria-describedby="kvm-help-" + s.id + " kvm-keys-" + s.id`.
   - Keep `data-kvm`, `tabindex="0"`, `id`, and `data-focus-key` exactly as they are.
2. **Tie the instructions to the console and make them keyboard-true.** Give the `.fine` paragraph after the console `id="kvm-help-" + s.id`, and change its text in both variants to: `"Click the console or Tab to it, then type. Keys go to " + d.name + ". Tab leaves the console. HTML5 viewer. Java and JNLP are unsupported."`
3. **Give the typed echo an id and an empty state.** Change the `.keys` element in both variants to `<div class="keys" id="kvm-keys-S">Typed: <span data-keys>…</span></div>`, where the span contains `esc(s.keys)` when `s.keys` is non-empty, and `nothing yet` when it is empty. `onKeyDown` already overwrites the span with `session.keys` on the first key, so the placeholder disappears without a `render.ts` change. Don't add `aria-live` (see Out of scope).
4. **Group and name the BIOS/OS toggle.** On the `.toggle` wrapper in both variants, add `role="group"` and `aria-label="Console screen for " + d.name`. Leave the buttons, their `aria-pressed`, and the RDP-failover variant's hard-coded pressed state as they are.
5. **Leave `src/ui/render.ts`, `src/domain/sessions.ts`, and `src/domain/demo.ts` unchanged.** The demo selectors and `mp1000-demo.spec.js` still match, because the classes and text content stay.
6. **CSS only if needed.** The global `:focus-visible` rule should already give the console a 3 px outline. Add a rule only if criterion 7 fails, for example because an ancestor clips the outline. Keep any such rule next to `.bios` (line 912).

Loading feedback: key echo and the BIOS/OS switch are synchronous local updates. No action here takes over 300 ms, so no busy state is added.

## Acceptance criteria

Every criterion is checkable in Playwright. Setup, following `e2e/navigation.spec.js`: use a 1440×900 viewport, sign in as `dsvs.operator`, push one KVM session onto `window.AccessDemo.state.sessions` (the same object shape as `navigation.spec.js` line 137, with `id: "kvm-a"`, `deviceId: "tray-01"`, `type: "kvm"`, `path: "acs"`, `screen: "os"`, `keys: ""`), and settle on `#/sessions`. The device name is the text of `.session.kvm .session-head h3 + p`. For the failover criteria, push a second session with `id: "kvm-b"`, `deviceId: "tray-02"`, and `rdpFailover: true`.

1. **The console is a named application.** `#kvm-kvm-a` has `role="application"` and accessible name `KVM console for <device>, OS screen`. After clicking the toggle's BIOS button, the re-rendered `#kvm-kvm-a` has accessible name `KVM console for <device>, BIOS screen`.
2. **The failover console is named.** `#kvm-kvm-b` (the `.rdp.kvm-take` element) has `role="application"` and accessible name `KVM failover console for <device of tray-02>, OS screen`.
3. **The console is described by its instructions and echo.** `#kvm-kvm-a` has an accessible description that starts with `Click the console or Tab to it, then type. Keys go to <device>. Tab leaves the console.` and ends with `Typed: nothing yet`, after whitespace normalization. Check with `toHaveAccessibleDescription` and a regex.
4. **The echo shows typed keys and the description follows.** Focus `#kvm-kvm-a` by keyboard (Tab from the BIOS/OS group, see criterion 6) and type `ls`, then press Enter.
   - `#kvm-kvm-a [data-keys]` has text `ls↵`.
   - `#kvm-kvm-a` has an accessible description that ends with `Typed: ls↵`.
   - `window.AccessDemo.state.sessions` entry `kvm-a` has `keys === "ls↵"`.
5. **No text is left unlabelled.** On a fresh session, `#kvm-keys-kvm-a` has text `Typed: nothing yet`. No element in `.session.kvm` has a bare `Typed` text with an empty `[data-keys]`.
6. **Keyboard order and leaving the console.** Focus the OS button in the first session's toggle.
   - Press Tab: `#kvm-kvm-a` is focused.
   - Type `a`: the echo shows `a`, and focus stays on `#kvm-kvm-a`.
   - Press Tab: focus moves to the media `select` (`#media-kvm-a`). The echo is unchanged (Tab is not typed).
   - Press Shift+Tab: `#kvm-kvm-a` is focused again.
7. **Focus is visible.** When `#kvm-kvm-a` and `#kvm-kvm-b` are focused by keyboard, each one's computed `outline-style` is not `none` and its `outline-width` is at least `2px`.
8. **The toggle is a named group.** `.session.kvm .toggle` for `kvm-a` has `role="group"` and accessible name `Console screen for <device>`. `page.getByRole("group", { name: "Console screen for <device>" }).getByRole("button", { name: "BIOS" })` resolves to exactly one element.
9. **Pointer behaviour is unchanged.** Clicking `#kvm-kvm-a` focuses it, and typing `x` shows `x` in its echo. A modifier chord (Control+A) types nothing.
10. **Blocked sessions are unchanged.** Push a third session with `id: "kvm-c"`, `path: "rm1048"`, `type: "kvm"`, then set `window.AccessDemo.state.rm1048` to a value other than `"healthy"` (for example `"down"`) and re-render (`sessionBlocked()` in `domain/single-master.ts` then returns true). Its card still renders `.fail` with an "Open on ACS" button and contains no `[role="application"]`.
11. **The demo still works.** `e2e/mp1000-demo.spec.js` passes unchanged: `.session.kvm .bios` still contains "Ubuntu 24.04" and then "Boot mode", and the demo highlights at `demo.ts` lines 623 and 632 still find their targets.
12. **The suite is green.** `npm test` in `prototypes/access-control` (vite build, then Playwright) passes with no skipped or removed tests. `access.spec.js` and `navigation.spec.js` pass unchanged. The total diff is under about 300 lines.
