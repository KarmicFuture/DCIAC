# Plan · 2026-11-22 · Outlet confirmation dialog: focus, containment, Escape

Branch: `ux/2026-11-21-cycle`  
Backlog item: **rank 1** in `docs/ux-backlog.md`. The outlet confirmation is a modal without initial focus, focus containment, or Escape, and the Control page stays in the tab order behind it (WCAG 2.4.3, 2.1.1, 4.1.2). Severity 4, effort M.

## Why this one

- **It is the highest-severity item, and it is about a destructive power action.** Off and Cycle drop live sessions and cut power to a GPU tray. A keyboard user who tabs behind the dialog can reach the Control table's buttons, the rail, and the alarm banner while a confirmation is pending.
- **The whole item fits in one cycle; no slice is needed.** Last cycle judged it too big, but reading the code, the work is smaller than that estimate:
  - The dialog markup lives in one function, `outletHoldHtml()` in `src/domain/outlet-policy.ts`.
  - The app already moves focus after a render through `state.focusField`, which `settle()` in `src/ui/render.ts` reads.
  - One `onKeyDown` handler in `render.ts` already owns Escape.
  - The estimate is about 90–110 changed source lines plus about 120 lines for one new spec. That is under the ~300-line budget.
- **Rank 2 (floor keyboard model) is still L.** It needs a keyboard model across floor, pod, rack, feed, and pipe elements in a 1,900-line view. Ranks 4 and 5 are severity 3.

## Problem (today, from the code)

`src/domain/outlet-policy.ts`:

- `actOutlet(n, op, source)` sets `state.outletGate = { phase: "confirm", … }` and calls `render()`. It never sets `state.focusField`. Focus stays on whatever was clicked, usually the Cycle or Off button in the Control table, which is now behind the backdrop.
- `outletHoldHtml()` returns `<div class="confirm-back"><section class="confirm-card" role="dialog" aria-modal="true" aria-labelledby="outlet-confirm-title">…`. Its focusable controls, in DOM order, are:
  - `#outlet-wo`, only outside a maintenance window
  - `#outlet-short`, only for a GPU tray
  - Cancel `[data-act="outlet-cancel"]`
  - Confirm `[data-act="outlet-confirm"]`

  Cancel and Confirm have no `id`, so `state.focusField` cannot target them.
- `submitOutletConfirm()` is `async` and `await`s `fetch("/api/v1/actions/outlet")`. Confirm gives no busy feedback and can be pressed again while the request is pending.
- On a validation or server error, the function sets `gate.error` and re-renders. The `lit-html` `unsafeHTML` slot then replaces the dialog DOM, so focus drops to `<body>`. The error `<p class="reason" role="alert">` is announced, but the keyboard user is no longer inside the dialog.
- `cancelOutlet()` clears the gate and re-renders without restoring focus.
- In the undo phase, `outletHoldHtml()` returns a `.toast` with an Undo button that has no `id`. When the hold commits, the toast disappears and focus, if it was on Undo, is lost.

`src/ui/toast.ts` / `src/ui/render.ts`:

- `toastHtml()` puts `outletHoldHtml()` in front of the toast text, and `paint()` renders it inside `<main id="content">` → `<div data-slot="toast" aria-live="polite" aria-atomic="true">`. As a result:
  - The whole dialog sits in a live region, so its content can be announced as a polite status update rather than as a dialog.
  - Any `inert` on `<main>` would also disable the dialog. The dialog must move out of `<main>` before the background can be made inert.
- `onKeyDown` handles Escape only after `if (typing) return;`, and only for floor panels. Escape inside `#outlet-wo` or `#outlet-short` does nothing, and Escape elsewhere doesn't close the dialog.

Callers that open the dialog: the Control row buttons (`views/control.ts`, `outletActions`), the DI-1 leak card "Shed Outlet N" buttons (`domain/leak.ts`), the Manage cycle button (`views/manage.ts`), and the analyzer suggestions (`render.ts` ~567). All of them go through `actOutlet`, which switches to `state.view = "control"`.

`actAll()` uses the native `window.confirm`, which is already modal and keyboard-accessible.

## User story

As a keyboard or screen-reader operator on Rack A14, when I press Cycle or Off on an outlet, I want focus to land inside the confirmation and stay there until I confirm or cancel. I want Escape to cancel, and I want focus to return to the button I started from. That way I can't act on the page behind a pending power change, and I never lose my place.

## Change (for the builder)

1. **Render the dialog outside `<main>`.**
   - Split `outletHoldHtml()` into `outletConfirmHtml()`, the confirm phase only, and the existing undo-toast output.
   - `toastHtml()` keeps only the undo toast and the regular toast.
   - In `paint()`, render `<div data-slot="confirm">${outletConfirmHtml()}</div>` as the **last child of `.shell`**, after briefing. It must not be inside any `aria-live` region.
2. **Make the background inert while the dialog is open.** After `litRender`, set `inert` on every element child of `#app` and of `.shell` except `[data-slot="confirm"]`. That covers the skip link, rail, `<main>`, lab, demo coach, and briefing. Remove `inert` from all of them when no confirm gate is open. Do this in a small helper called from `paint()`. `lit-html` doesn't bind `inert`, so setting it imperatively is safe.
3. **Give the dialog controls ids.** Use `id="outlet-cancel"` and `id="outlet-confirm"` on the dialog buttons, and `id="outlet-undo"` on the undo-toast button. Give the openers stable ids:
   - Control row buttons: `id="outlet-<n>-<op>"`, for example `outlet-9-cycle`.
   - Leak card buttons: `id="leak-shed-<n>"`.
4. **Initial focus.** When `actOutlet` opens the confirm gate, store `gate.opener` as `document.activeElement.id` (empty if none). Then set `state.focusField` to the first control that exists: `outlet-wo`, then `outlet-short`, then `outlet-cancel`. The fallback is Cancel, not Confirm, because the action is destructive. Add `opener: string` to the `outletGate` type in `src/types.ts`.
5. **Keep focus inside after errors.** When `submitOutletConfirm` sets `gate.error`, set `state.focusField`:
   - Missing work order: `outlet-wo`.
   - Wrong short name: `outlet-short`.
   - Server or policy refusal: `outlet-cancel`.
6. **Tab wraps.** In `onKeyDown`, while a confirm gate is open, handle Tab and Shift+Tab before any other check. Tab on the last enabled focusable in `.confirm-card` moves to the first. Shift+Tab on the first moves to the last. Use `preventDefault` only when wrapping.
7. **Escape cancels.** In `onKeyDown`, while a confirm gate is open, Escape calls `cancelOutlet()`. It must run **before** the existing `typing` early return, so it also works from inside `#outlet-wo` and `#outlet-short`. It must also take priority over the floor-panel Escape.
8. **Return focus.** `cancelOutlet()` sets `state.focusField` to the return target:
   - `gate.opener` if that element exists after render and is not disabled.
   - Otherwise the Control row button `outlet-<n>-<op>`.
   - Otherwise `content` (the `<main>` element, which has `tabindex="-1"`).

   Put this lookup in one small helper. `undoOutlet()` uses the same target. When a hold commits (`commitHold`) and `document.activeElement` is `#outlet-undo`, use the same target too. If focus is elsewhere, `commitHold` does not move it.
9. **Focus Undo after confirming.** When `submitOutletConfirm` succeeds and enters the undo phase, set `state.focusField = "outlet-undo"`.
10. **Busy state.** While the `fetch` is pending:
    - Set `gate.busy = true` and re-render.
    - Confirm shows the label `Confirming…`, `aria-disabled="true"`, and `aria-busy="true"`.
    - A second activation is ignored, because `submitOutletConfirm` returns early when `gate.busy` is set.
    - Clear `busy` on every exit path.

    Use `aria-disabled`, not `disabled`, so focus stays on the button.
11. **No visual restyle.** The existing `.confirm-back` and `.confirm-card` CSS already positions the dialog with `position: fixed`, so moving the slot changes nothing visually. If the focus ring on `.confirm-card` buttons or inputs isn't visible against `--panel`, add a `.confirm-card :focus-visible` rule reusing `--focus`. Otherwise leave `styles.css` alone.

## Acceptance criteria

Every criterion is checkable in Playwright. Setup: sign in as `dsvs.operator`, go to `#/control`, and use Outlet 9 · GPU Tray 06, which is enabled by default, as in `access.spec.js`. Outside a maintenance window, the dialog shows `#outlet-wo` and `#outlet-short`.

1. **Initial focus.** After clicking the row's Cycle button, `page.getByRole("dialog", { name: "Cycle Outlet 9" })` is visible and `#outlet-wo` is focused (`toBeFocused()`).
2. **Initial focus without fields.** With a maintenance window open and an outlet bound to a non-GPU device (so neither field renders), opening Cycle focuses `#outlet-cancel`. Open the window via `#/simulate` or `window.AccessDemo`, whichever the existing specs use.
3. **Not in a live region.** `[data-slot="toast"] [role="dialog"]` and `[aria-live] [role="dialog"]` both have count 0 while the dialog is open. `[data-slot="confirm"] [role="dialog"]` has count 1.
4. **Background is inert.** While the dialog is open, `main#content`, the rail `nav`, and the skip link each have the `inert` attribute. `[data-slot="confirm"]` and its ancestors don't. After the dialog closes, none of them do.
5. **Tab is contained.** From `#outlet-wo`, pressing Tab 4 times visits `#outlet-short`, Cancel, Confirm, and then `#outlet-wo` again. Shift+Tab from `#outlet-wo` focuses Confirm. At no point does `document.activeElement` sit outside `.confirm-card`.
6. **Escape from a field cancels.** With focus in `#outlet-wo` (optionally with text typed), Escape closes the dialog (`getByRole("dialog")` count 0) and power is unchanged: Outlet 9's power badge still reads `On`. No `outlet cycle` audit row is added.
7. **Focus returns to the opener.** After Escape (criterion 6) or clicking Cancel, `#outlet-9-cycle` is focused. When the dialog is opened from the DI-1 leak card's "Shed Outlet N" button, Cancel returns focus to `#leak-shed-<N>`.
8. **Errors keep focus inside.** Confirm with an empty work order shows the `role="alert"` text "A work order number is required outside a maintenance window." and focuses `#outlet-wo`. Fill the work order but type the wrong short name, and Confirm focuses `#outlet-short` with the "Type the device short name tray-06 to confirm." alert.
9. **Busy feedback.** Delay `/api/v1/actions/outlet` with `page.route` (for example by 800 ms) and click Confirm. During the delay, Confirm has text `Confirming…`, `aria-busy="true"`, and `aria-disabled="true"`. A second click doesn't send a second request: count the requests in the route handler, and the total must be 1.
10. **Success moves focus to Undo.** After a valid Confirm, the dialog closes, the toast reads "Cycle Outlet 9 · GPU Tray 06 … Undo within", and `#outlet-undo` is focused. Pressing Enter on it undoes the change ("Outlet change undone. Power was not changed.") and focuses `#outlet-9-cycle`.
11. **Commit doesn't strand focus.** With `#outlet-undo` focused, `window.AccessDemo.finishOutletHold()` commits the change, and then `#outlet-9-cycle` is focused, not `body`.
12. **Visible focus.** Every focused control in criteria 1, 5, and 10 has a computed `outline-style` that is not `none`.
13. **No regressions.** The existing "Operator can cycle a bound outlet and the act is audited" test in `e2e/access.spec.js` passes unchanged. `actAll` still uses `window.confirm`. Floor Escape still closes floor panels when no dialog is open: `hall.spec.js`, `stage.spec.js`, and the floor specs pass.
14. **Suite green.** `npm test` in `prototypes/access-control` (vite build, then Playwright) passes with no skipped or removed tests. The total diff is under about 300 lines.
